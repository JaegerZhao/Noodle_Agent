# 产品需求与实现边界

更新：2026-10-29。本文是当前需求入口，历史规划和逐轮结果统一见[开发更新日志](DEVELOPMENT-LOG.md)。

## 项目定位

Noodle Agent 是基于 DeepSeek Harness 的本地个人知识 Agent。将教材、课件、论文等 PDF 转换为有来源的结构化笔记，再维护跨资料 Concept、知识体系和引用问答。

本地保存知识、版本、任务和资产；解析、文本生成、必要视觉理解、嵌入及重排使用配置的外部服务，不代表全部模型在本机推理。

## 核心对象

| 对象 | 职责 |
| --- | --- |
| Source / SourceRevision | 保存原始资料身份、版本、解析与删除状态 |
| Atomic / Section | 一份资料内相对完整的主题笔记，含正文、公式、图片和小节证据 |
| 来源阅读投影 | 按来源目录组装 Atomic，形成连续阅读页面，不另调用模型改写整篇 |
| Concept | 跨资料维护的稳定知识对象，形成浓缩框架与必要增量 |
| 知识体系 / MOC / 关系 | 组织阅读路径、领域、父子和语义链接，不复制知识正文 |
| Chunk | 从当前有效 Atomic、Concept 正文生成的检索片段 |

Atomic 不要求一页一篇；一个 Atomic 不必新建一个 Concept；MOC、原始 PDF 不直接充当当前 RAG 事实语料。

## 用户流程与当前实现

| 用户目标 | 当前实现及边界 |
| --- | --- |
| 导入 PDF | 登记新版本和持久化任务；兼容缓存按来源、解析参数和资产验证 |
| 区分资料类型 | 教材优先按原目录分章；课件聚合连续主题；论文突出方法、架构、实验与限制 |
| 尽早阅读 | Atomic 发布后可读，索引完成后可检索；Concept 在后台继续 |
| 持续更新知识 | 教材默认 FOUNDATION，课件、论文默认 SUPPLEMENT；按对象身份和贡献决定新增或复用 |
| 资料管理 | 文件夹、重命名、排序、批量移动、删除和恢复；这些操作不直接重写正文 |
| 阅读原文 | 完整资料目录、正文高亮、笔记与 PDF 定位、阅读位置恢复 |
| 浏览知识 | Concept 卡片和正文、来源笔记、直接父子知识、多体系树和关系图 |
| 对话操作 | 统一通过 DSH 调用 17 个领域工具；支持问答、查找、任务状态及受审批操作 |
| 修改和撤回 | 新建修订，按版本比较提交；来源失效沿贡献、图和索引传播 |
| 导出迁移 | 标准 Markdown、Obsidian 阅读包、Vault 回流与完整恢复包 |

## 生成与质量约定

主流程：PDF → MinerU → 类型与目录规划 → Atomic → Atomic 索引与阅读；Atomic 同时触发 Concept 归属、构建、索引和结构整理。

- 主题应综合，封面、版权、纯导航不应成为知识笔记。
- 主要标题和小节标题使用中文，保留有意义的英文术语与缩写；避免冗长范围标题和重复标题。
- 有教学价值的图表和论文关键架构图应保留。整页截图可以作为理解上下文，不应直接冒充文章配图。
- Concept 以浓缩框架为主，补充来源带来有效增量或证据，不机械追加所有 Atomic 正文。
- Atomic 审查按小节执行：草稿 → Flash 审查一次 → 有意见修复一次 → 必要格式与结构验收 → 发布并记录意见。
- 格式恢复必要时可使用 Pro；修复后不因数值、代码语义或没有变化而循环打回。空白乱码、来源身份、无效资源和发布结构等必要检查保留。
- 审查意见和警告应保留；发布成功与内容逐句正确是不同结论。

模型分工按配置与 `cost_policy.py` 决定：默认规划、中文标题、Concept 对象规划及归属使用 Pro；常规正文、检查、修复使用 Flash。历史 A/B 模式不是额外生产主路径。

## 版本与证据约定

- 数据库及不可变文件是权威数据；页面、图和 Markdown 是投影。
- 引用绑定笔记版本、小节和原 PDF 页码，不依赖标题猜测来源。
- 来源删除或替换后，旧内容退出正常阅读与检索；保留历史和可恢复记录。
- 作者编辑、并发版本比较、任务租约和幂等保护继续生效。
- 语义图可有多个关联方向；阅读层级不能产生非法环，多父对象通过引用投影展示。

## 成本、时间和状态

目标是在保证有效内容和可追溯性的前提下，使约 60 页课件全流程争取低于 15 分钟，Atomic 至组装、索引争取低于 10 分钟。这是待固定基准验证的目标，不是对任意文件的时限承诺。

优化优先级：复用兼容解析与向量、压缩重复证据、局部增量、有界并发、按需视觉、合并重复派生任务。调用预算用于观察异常，不因普通超额强行终止任务。

界面区分排队、实际执行、暂停和后台维护；供应商未返回的用量不填成零。历史记录跨度不冒充净执行时间。

重新导入并要求重新生成时，可以只复用兼容 MinerU 结果；后续规划、视觉与正文是否复用应遵守该次任务策略，不能把旧规划暗中当成新结果。

## 当前重点与边界

主要功能已有实现和真实样本，但还需处理完整发布门禁、后台通道健康、结构覆盖状态、事务时长、历史索引维护，以及独立内容评测。具体结果与优先级见[验证说明](TESTING.md)。

当前面向本地单用户。多租户、高可用集群和音视频生成不是已交付能力。后续改造应保留当前可用路径与原始回执，避免为单份资料增加通用流程无法解释的特例。
