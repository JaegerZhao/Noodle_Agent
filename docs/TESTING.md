更新：2026-10-29。测试、真实模型验收和独立内容评测分别记录；不以历史数量替代当前结果。

## 检查入口

| 层次 | 命令 | 范围 |
| --- | --- | --- |
| 源码卫生 | `npm run check:release` | 依赖清单、敏感模式、运行文件与大小限制 |
| TypeScript | `npm run typecheck`、`npm test` | 工具、Provider、状态与前端回归 |
| 生产构建 | `npm run build` | 插件和浏览器资源构建 |
| Python 静态检查 | `python -m ruff check --no-cache services/noodle/src services/noodle/tests` | 全仓规范及常见错误 |
| Python 回归 | `npm run test:python` | 独立临时库中的领域、版本、恢复和接口 |
| 启停检查 | `npm run test:launcher` | 隔离 API、Worker、Harness 启停 |
| 离线集成 | `npm run smoke:workflow` | 注入提供者的完整流程，不代表真实内容质量 |

直接执行 pytest 时使用新的 `--basetemp`，不要复用含资料的目录。默认回归使用 fixture；真实生成和模型问答另行安排，不能把发布检查变成付费重跑。

## 内容和效果验收

- Atomic：主题完整性、中文标题、关键公式条件、例子、配图和来源页码。
- Concept：同对象归并、错合并、净新增、浓缩程度、来源角色、媒体和撤回。
- RAG：召回、小节命中、引用支持、范围、失效来源、拒答及答案准确性。
- 生命周期：作者修订、来源替换、删除恢复、并发版本、索引和图更新。
- 成本时间：原件范围、模型、调用、输入/输出/缓存用量，排队、执行、暂停及端到端分开记录。

既有 36 题主要覆盖词法召回、小节和范围，不是完整回答准确率。历史 194 篇 Atomic 的 Concept 冷启动验收也不是全书逐句准确性的证明。

固定质量集应覆盖教材、课件、论文、公式、图片和负例；保留首次失败结果。离线评测不应演变为生产中的重复语义复审。

## 精简与 Git 分批原则

先固化完整可运行基线，再按可靠性、性能状态、兼容隔离、索引维护、效果评测分批提交。一次提交同时包含必需的新模块、旧入口删除、契约与回归，不能随意按目录拆出无法运行的中间版本。

兼容代码先列调用者、隔离、验证，再删除。数据库迁移、旧记录读取、原始回执、租约和版本保护、正式资产与冻结基线继续保留。

所有验收说明输入和版本。不得将合成提供者、缓存回放、修复后恢复或人工等待包装成一次无人干预冷启动结果。
