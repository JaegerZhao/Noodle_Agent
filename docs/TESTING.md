# 测试策略与当前限制

## 验证层次

| 层次 | 入口 | 验证内容 |
| --- | --- | --- |
| 源码卫生 | `npm run check:release` | 配置与锁文件一致性、敏感模式、本地文件和大小限制 |
| TS 契约 | `npm run typecheck`、`npm test` | 工具参数、审批调用、HTTP DTO 和错误传播 |
| Python 回归 | `python -m pytest services/noodle/tests` | 版本、质量、证据、归并、删除恢复和接口 |
| 静态检查 | `python -m ruff check services/noodle/src services/noodle/tests` | Python 代码规范与常见错误 |
| 隔离链路 | `python scripts/delivery-check.py` | API / Worker / Harness 的真实进程边界，使用合成数据 |
| 浏览器 | 上述命令加 `--browser` | 阅读器、PDF.js、Markdown 与 KaTeX |
| 真实服务 | 自有资料与本地密钥 | 解析质量、生成内容、外部服务失败和实际问答 |

测试默认采用 mock / fixture，不消耗模型额度。`delivery-check.py` 不读取用户的 `.env`、数据库或知识库。测试临时目录与报告不进入 Git。Windows 若系统 pytest 临时目录权限异常，可显式指定全新的 `.runtime/pytest-<run-id>` 为 `--basetemp`。

## 评测内容质量

真实模型评测应单独记录资料范围、模型配置、问题集与失败样例。笔记抽查可以关注：主题边界、关键公式、图文对齐、页码引用、概念重复与阅读结构。RAG 应分别检查检索覆盖和回答是否由检索证据支持，不能仅根据回答流畅度评价效果。

跨文档归并需要覆盖互补、重复、冲突、相似但不同概念、删除唯一来源、恢复资料及并发编辑。除了新正文，也应检查旧来源是否退出检索、知识版本是否正确绑定来源、质量失败是否保留待复核状态。

源码扫描采用启发式规则，不能保证识别全部凭据。贡献者仍须检查待提交 diff；出现密钥泄露时应立即撤销密钥，不能只删除工作区文件。

## 当前限制

- 面向本地个人使用，缺少完整多用户认证、权限和租户隔离。
- SQLite、任务租约与模型并发满足当前工程边界，尚未验证大规模多实例吞吐。
- 生成与 Judge 依赖模型判断，正确性需要人工抽查；没有公布可泛化的真实资料准确率指标。
- 混合检索使用本地评分排序，没有独立 cross-encoder 重排服务。
- 自动知识编排优先适配已有分组，复杂体系重组、Concept 拆分和语义冲突解决仍需完善。
- 来源删除是逻辑删除，尚无覆盖全部产物、历史与备份的永久清除流程。
- 主服务保留部分旧 LangGraph 兼容代码，默认运行链路不使用旧 Agent。
- 当前 Python 依赖使用版本范围，npm 有锁文件；Python 环境仍可能随兼容版本更新产生差异。
- 模型接口、套餐、额度和解析效果由外部服务决定。云端真实效果与离线 fixture 测试需要分别验收。
